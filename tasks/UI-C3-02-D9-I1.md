## Objective

Make ProofPilot AI ready for exactly one owner-authorized Baseten live video
analysis request through Zone L, while preserving the fully functional mock
workflow as the fallback.

## Scope (12 items)

1. **Owner-started runtime wiring** for the dormant Baseten transport in
   `scripts/c3-live-analysis.ts`: explicit `--live` flag only (default off).
   No auto-enable via env presence, argument fallthrough, or UI state.
2. **Exact model/endpoint verification.** Proposed ID:
   `meta-models/muse-spark-open` (Baseten Oct 15, 2026 changelog example
   against `POST https://inference.baseten.co/v1/chat/completions`).
   Known conflict: another Baseten library example shows
   `meta/Muse-Spark-Open-816B-A42B`; Meta's deployment guide names
   `meta-models/Muse-Spark-Open-816B-A42B` (checkpoint, not a Model API ID).
   Record all three; refuse every alias by exact match — never translate or
   substitute. The configured `BASETEN_MODEL` value is validated separately
   by exact equality and may legitimately differ from the proposal until D9.
3. **Fail-closed live mode + separate activation gate.** Three independent
   conditions, all required: `--live` flag, owner-injected credentials (item
   4), and D9 approval (`validateLiveModel`, still `null`). CLI refuses to
   start live mode while D9 is `null`.
4. **Owner-only credential injection.** The owner-started CLI reads exactly
   `BASETEN_API_KEY`, `BASETEN_API_BASE_URL`, `BASETEN_MODEL` from its own
   process environment after the configuration and activation gates. Never
   read, print, or expose the key during implementation or testing; never
   read the repository `.env.local`. `packages/live-analysis/src`,
   dashboard, tests, CI, and generated evidence must never receive the key
   (static boundary tests enforce this; only `scripts/c3-live-analysis.ts`
   may name these variables).
5. **Terminal pairing, single-use hash/byte/action-bound permits, one-shot
   live-attempt authorization.** Reuse the existing permit ledger; live
   attempts use the separate `live-attempts.ts` ledger (MAJOR-2/3 machinery).
6. **Non-rearmable attempt record.** New durable, tamper-evident spent-run
   record (`live-spent-record.ts`, hash-chained JSONL, mode 0600): every
   authorized send is recorded at the send boundary; effective budget =
   configured − recorded. A live budget > 0 without a record path refuses
   companion startup. Restarting the companion cannot recreate spent
   authorization; a corrupt record fails closed.
7. **Mock/live separation.** Live requests are governed by the live ledger
   only — the dormant `quotaFor(kind)` coupling is removed for the live path
   (mock quota untouched by live attempts and no longer gating them).
   `/api/status` reports mock quota unchanged plus a clearly labeled live
   section with correct provenance.
8. **One fixed validated synthetic F01 request.** Analysis cap stays
   `ANALYZE_MAX_TOKENS = 1024`. Optional `liveMediaSha256` pin refuses live
   attempts on non-matching staged bytes. The runbook proposes the certified
   F01 mobile clip (SHA-256 `e9df68…afdf`) pending owner D3.
9. **No retries, fallbacks, redirects, automatic model discovery, or
   background provider requests.** One POST per approval (existing).
10. **Live response UI** shows Baseten provider, exact model, run ID,
    observations, uncertainty, actual reported token usage, `UNVERIFIED`
    status (existing Zone L provenance; extend only if a row is missing).
11. **Mock workflow preserved** as the fallback (default path byte-identical).
12. **Owner-only preflight + execution runbook** (`docs/UI-C3-02-D9-RUNBOOK.md`):
    recording, cancellation, cleanup, post-run reconciliation, disable/re-lock.
    Redacted demo steps; no secrets.
